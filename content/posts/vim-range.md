## vim 범위(range)에서 주소 지정 방식

vim에서는 줄 범위(line range)를 받는 Ex 명령이 많다. 보통, Ex 명령은 특정 줄을 대상으로 하는 편집 명령이 많다. `[range]`는 그 대상이 되는 줄을 지정하는 것이다. 보통 생략하면, 현재 커서가 있는 줄(current line)을 대상으로 하는 경우가 많다. 다만,`:write`이나 `:global`는 생략하면, 버퍼 전체(`1,$`)를 대상으로 한다.

`[range]`는 특정 줄을 가리키는 주소를 여러 개 받는데, 명령마다 받아서 사용하는 주소의 개수가 다를 수 있고, 주소 하나는 숫자로 줄번호를 지정하거나 `/pattern/`과 같이 줄 내용 매칭으로 줄을 가리킬 수도 있다. 그 외에 줄 주소로 사용할 수 있는 패턴은 다음과 같다.

- `{number}`: 절대주소
- `.`: 현재 줄
- `$`: 파일의 마지막 줄
- `%`: 파일의 모든 줄 (`1,$`와 동일)
- `*`: `'<,'>`와 동일. 가장 최근에 선택된 Visual area의 라인들
- `'x`: mark `x`의 위치
- `'X`: mark `X`의 위치 (대문자 마크는 글로벌 마크인데, 위치가 다른 파일에 있는 경우, range로 사용 못함)
- `'[`: 가장 최근 변화(change) 또는 복사(yank)된 영역의 첫번째 라인
- `']`: 가장 최근 변화(change) 또는 복사(yank)된 영역의 마지막 라인
- `'<`: 가장 최근 선택된 visual area의 첫번째 라인 
    - 현재 선택된이 아니라, “최근 선택된”이다. visual area를 해제했더라도 이 주소는 최근에 선택했던 영역의 시작을 가리킨다.
- `'>`: 가장 최근 선택된 visual area의 마지막 라인
- `''`: 가장 최근 점프하기 직전 위치의 라인, 또는 마지막 `m'`, `` m` ``명령으로 지정한 위치
- `'"`: 마지막으로 버퍼를 떠났을(exiting) 때 커서 위치의 라인
- `'^`: 마지막으로 Insert 모드를 끝냈을 시점의 커서 위치의 라인
- `'.`: 마지막으로 버퍼가 수정되었을 때 커서 위치의 라인
- `'(`: 현재 문장의 첫번째 문자가 있는 라인
- `')`: 현재 문장의 마지막 문자가 있는 라인
- `'{`: 현재 커서를 포함하는 문단 이전의 빈 줄 라인
- `'}`: 현재 커서를 포함하는 문단 이후의 빈 줄 라인
- `/{pattern}/`: 커서 다음에 지정한 패턴을 포함하는 줄
- `?{pattern}?`: 커서 전에 지정한 패턴을 포함하는 줄
- `\/`: 이전에 사용한 패턴을 포함하는 다음 줄
- `\?`: 이전에 사용한 패턴을 포함하는 이전 줄
- `\&`: 이전에 사용한 치환(substitute) 패턴을 포함하는 다음 줄

위의 주소 지정자에는 `+` , `-` 또는 숫자를 붙여서 `+1`, `-2` 같은 offset 을 하나 이상 붙일 수 있다. 숫자를 생략하면 `1`을 붙인 것과 같다. 즉, `+`는 `+1`과 같다. 이 offset을 다 합친 것이 최종 주소가 된다. 주소 지정자 없이 offset만 나면, `.`이 생략된 것처럼 동작한다. 

예를 들어, `:put` 명령은 주소를 하나 받는 명령이고, 지정한 줄 다음 줄에 레지스터의 값을 붙여넣는 명령이다 즉, `:put a`는 현재 커서가 있는 줄 다음 줄에 `a`레지스터의 값을 붙여넣는데, `:7put a`는 7번 줄 다음에 붙여넣고, `:/some/put a` 는 커서 다음에`/some/`패턴을 포함하는 줄 다음에 붙여넣는다.

`:s` 명령은 주소를 최대 두 개까지 받는 명령이고, `[range]`주소의 값에 따라 다음과 같이 치환을 할 줄을 선택한다.

- `:s/{pattern}/{string}/[flags]` : 생략하면, 현재 라인에서 치환을 실행한다.
- `:3s/{pattern}/{string}/[flags]` : 3번줄에서 치환을 실행한다.
- `:/some/s/{pattern}/{string}/[flags]`: 현재 커서 이후로 `some`패턴을 포함한 줄에서 치환을 실행한다.
- `:3,7s/{pattern}/{string}/[flags]`: 3~7줄 각각 치환을 실행한다. (즉, 총 5개줄)
- `:3,/some/s/{pattern}/{string}/[flags]`: 현재 커서 이후로 `some`패턴을 포함한 줄을 찾고, 3번 줄부터 그 줄까지 각각 치환을 실행한다.
- `:/some/,/other/s/{pattern}/{string}/[flags]`: 현재 커서 이후로 `some`패턴을 포함한 줄과, `other`패턴을 포함한 줄을 찾고, 각각을 시작줄, 끝줄로 해서 그 사이의 모든 줄에서 각각 치환을 실행한다.

## 명령이 받아들이는 주소 개수보다 많이 전달한 경우, 뒤쪽에 있는 주소들을 사용한다.

예를 들어 substitute는 최대 2개의 주소를 받아서 시작~종료 범위로 사용하는 명령이다. 이 명령에 다음과 같이 주소를 3개 전달한 경우,

```bash
:2,5,10s/pattern/replacement/
```

뒤에 있는 `5`,`10`만 사용하여 다음과 같이 전달한 것처럼 실행된다.

```bash
:5,10s/pattern/replacement
```

## 주소들의 두 가지 구분자는 커서 위치를 업데이트하느냐 여부가 다르다. `,`는 커서 위치를 업데이트하지 않고, `;`는 업데이트한다.

여러 개의 주소를 `,`로 구분할 수도 있고, `;`로 구분할 수도 있는데, 주소를 해석하는 동안 커서의 위치가 달라진다. `,`로 구분하는 경우, 커서의 위치를 업데이트하지 않는다. 즉, 명령을 실행할 때의 커서의 위치를 기준으로 주소를 찾는다. 절대 주소에는 영향이 없겠지만, `/{pattern}/`,`?{pattern}?`같은 주소는 현재 커서의 위치 기준으로 패턴을 찾기 때문에 영향이 있다. `;`로 구분하는 경우, 다음 주소로 넘어가기 전에 커서를 이전 주소 위치로 업데이트한다. 예를 들어 `:1,/pattern/s`과 같이 하면, `/pattern/`을 찾을 때, 이 명령을 실행할 시점의 커서의 위치를 기준으로 찾는다. 이 명령을 8번 줄에서 하는 경우, 8번 줄 이전에 `pattern`을 포함하는 줄이 있어도, 8번 줄 이후에 `pattern` 을 포함하는 줄을 찾아서 종료 줄로 지정하는 것이다. 반면, `:1;/pattern/s`와 같이 하면, 시작줄 `1`번을 선택한 후 커서의 위치를 `1`번 줄로 옮긴 후, 다음 주소를 검색한다. 즉, 커서가 1번 위치에 있는 상태에서 `pattern`을 포함하는 줄을 찾으니 결과가 달라질 수 있다. 그리고 명령이 받는 주소 개수보다 많이 전달하는 경우, 앞의 주소는 버린다는 동작과 같이 이용하면, `:1;/start/;/end/s` 이렇게 3개의 주소를 주고, 첫번째 주소 `1`은 검색 기준을 위한 커서를 `1`번 줄로 옮기는 용도로만 쓰고, `substitute` 명령에는 전달 안 할 수도 있다. 이렇게 하면, 현재 커서의 위치와 관계 없이, 항상 첫줄부터 검색해서 `start`를 포함한 것을 찾고, 그 이후로 `end`를 포함하는 것을 찾도록 할 수 있는 것이다.

예를 들어, 다음과 같은 텍스트가 있다고 하자.

```bash
1 quick jump
2 vim exercise
3 frontend developer
4 good people
5 system debugging
6 coffee cup
7 modern software
8 developer journey
9 running man
10 design system
```

커서가 6번에 있는 상황에서 `:2,/system/s/$/ 👈/` 와 같이 하면, 2부터 10번까지 명령이 실행되어서 다음과 같이 된다. 5번에도 `system`이라는 텍스트가 있지만, `2,`는 커서를 2번으로 옮기지 않기 때문에 6번을 기준으로 `system`을 검색하기 때문이다.

```bash
1 quick jump
2 vim exercise 👈
3 frontend developer 👈
4 good people 👈
5 system debugging 👈
6 coffee cup 👈
7 modern software 👈
8 developer journey 👈
9 running man 👈
10 design system 👈


```

반면, `:2;/system/s/$/ 👈/`와 같이 하면, 2번부터 5번까지 명령이 실행된다. `2;`에 의해 커서가 2번으로 옮겨 간 상태에서 `system`을 검색하기 때문이다.

```bash
1 quick jump
2 vim exercise 👈
3 frontend developer 👈
4 good people 👈
5 system debugging 👈
6 coffee cup
7 modern software
8 developer journey
9 running man
10 design system


```

이번엔 커서를 6번에 둔 상태에서 `:/developer/,/system/s/$/ 👈/`를 해보자. 다음과 같이 6번 이후에서 검색되어 8~10번이 선택되었다.

```bash
1 quick jump
2 vim exercise
3 frontend developer
4 good people
5 system debugging
6 coffee cup
7 moder software
8 developer journey 👈
9 running man 👈
10 design system 👈


```

`:1,/developer/,/system/s/$/ 👈/`를 하면, 처음 `1`번 주소는 `s`에 전달되지 않고, `1,`은 커서를 옮기지도 않으므로 위와 결과가 동일하다. 반면, `:1;/developer/,/system/s/$/ 👈/`를 하면, `1;`에 의해 커서가 1번으로 옮겨지고, 1번 기준으로 `developer`와 `system`을 찾아서 3번 5번을 찾은 뒤, 3~5번 줄에서 치환을 실행한다. 

```bash
1 quick jump
2 vim exercise
3 frontend developer 👈
4 good people 👈
5 system debugging 👈
6 coffee cup
7 moder software
8 developer journey
9 running man
10 design system


```

`:1;/system/,/developer/s/$/ 👈/` 는 어떨까? `1`번으로 커서를 옮긴 후, 1번 기준으로 `system`과 `developer`를 찾으면, 각각 5번과 3번이다. 시작 주소가 더 크므로 순서를 바꾸겠냐는 프롬프트를 띄운 후 confirm 하면, 3~5번 줄에서 실행한다. 즉, 위와 동일하다.

```bash
1 quick jump
2 vim exercise
3 frontend developer 👈
4 good people 👈
5 system debugging 👈
6 coffee cup
7 moder software
8 developer journey
9 running man
10 design system


```

반면, `:1;/system/;/developer/s/$/ 👈/` 를 하면, `1`번으로 커서를 옮겨 `1`번 기준으로 `system`을 찾아서 `5`번을 얻고, `/system/;`에서 `;`로 구분하였으므로 다음 주소로 가기 전에 또 커서를 찾은 `5`번으로 옮겨서, `developer`를 `5`번을 기준으로 그 이후에서 찾는다. 따라서 `3`번이 아니라 `8`번이 선택되어서 3~8번 줄에서 실행하게 된다.

```bash
1 quick jump
2 vim exercise
3 frontend developer
4 good people
5 system debugging 👈
6 coffee cup 👈
7 moder software 👈
8 developer journey 👈
9 running man
10 design system


```

## range를 받아서 해석하고 다루는 방식은 명령마다 다를 수 있다.

### <br>

### range을 일괄로 한번에 처리하는 명령들

`[range]`를 범위를 다루는 방식이 명령마다 조금씩 다를 수 있다. 특히, 명령에서 여러 줄에 걸친 편집을 해서 편집 결과로 줄의 번호가 달라질 때 영향이 나타난다.

`:delete`(`:d`) 같은 명령은 범위를 받아서 한번에 명령을 처리한다. (줄마다 명령을 개별적으로 실행하지 않는다.) 예를 들어, 다음 명령은 9~11줄은 한번에 삭제한다.

```bash
:9,11d
```

`:join`(`:j`) 명령도 한번에 처리한다. 다음 명령은 9~11줄을 하나씩 합치는 게 아니라 한번에 합쳐서 수정한다.

```bash
:9,11j
```



### range의 각 행마다 실행하는 명령들

반면, `:s`, 같은 명령은 줄마다 반복하여 명령을 실행한다. 다음 명령은 9,11 범위에 대해서 한번에 치환 명령을 처리하는 게 아니라 9줄에서 한번, 10줄에서 한번, 11줄에서 한번 이렇게 세 번 치환 명령을 실행한다.

```bash
:9,11s/pattern/replacement/
```

만약 다음과 같이 치환 명령에 의해 줄이 변하는 경우에는 내부적으로 줄의 이동을 추적해서, 원래 줄에 가서 치환 명령을 실행해준다고 한다.

```bash
:9,11s/\n/ /
```

예를 들어, 위의 명령은 라인 끝에 있는 개행문자를 공백으로 변환하는데, 9행에서 실행하면, 10행이 9행으로 합쳐지고, 원래 11행이 10행으로 간다. 

다음 예제에서 `|`왼쪽에 있는 것은 에디터의 라인 번호이고, `(9)`같은 건 텍스트 내용이라고 하자.

원본

```bash
 9| (9)안녕하세요.
10| (10)종완입니다.
11| (11)반가워요.
12| (12)좋은 하루 되시구요.
13| (13)잘 부탁드립니다.
14| (14)감사합니다.
```

9행에서 치환을 실행하면 다음과 같이 된다.

```bash
 9| (9)안녕하세요. (10)종완입니다.
10| (11)반가워요.
11| (12)좋은 하루 되시구요.
12| (13)잘 부탁드립니다.
13|
14| ...생략

```

위 상황에서 두번째 10행의 치환 실행은 현재 10행인 `(11)` 라인이 아니라 원래 10행이었고, 지금은 9행이 된 `(10)`라인에서 진행된다. 이 줄 번호를 substitute 명령 내부적으로 추적한다는 것이다.

```bash
 9| (9)안녕하세요. (10)종완입니다. (11)반가워요.
10| (12)좋은 하루 되시구요.
11| (13)잘 부탁드립니다.
12| (14)감사합니다.
13| ...생략
14| ...생략
```

그리고 세번째 11행 치환 명령도 원래 11행이었고, 지금은 9행이 된 `(11)`이 있는 라인에서 진행된다. 이렇게 9,10,11,12행까지 모두 합쳐지는 것이다. 

```bash
 9| (9)안녕하세요. (10)종완입니다. (11)반가워요. (12)좋은 하루 되시구요.
10| (13)잘 부탁드립니다.
11| (14)감사합니다.
12| ...생략
13| ...생략
14| ...생략
```

`:9,11join` 이 9~11행 3개만 합치는 것과 달리, `:9,11s/\n/ /` 명령은 4개의 행을 합쳤다. 명령이 3번 일어나고 명령마다 한 개씩 윗줄과 합쳤기 때문이다. 

참고로 실행할 줄을 찾아갈 때는 변경된 줄을 따라가긴 하지만, 명령 자체는 순차적으로 실행된다. 즉, 첫번째 행에서 실행한 결과가 두번째 행을 실행할 때 관찰된다. 치환 문자열에 `\=line(".")` 같은 걸 넣어서 현재 번호를 출력하면, 앞쪽 행 명령에서 변경된 라인이 보인다는 것이다.

<br>

### 행별 실행을 하는데, 변경 라인을 추적하지 않고, 현재 줄번호 기준으로 실행하는 명령

`:normal`이 대표적이다. 이건 `:s`처럼 편집 후 라인이 변경되었을 때, 원래 라인을 찾아서 다음 명령을 실행하는 게 아니라, 현재 기준으로 단순히 해당 줄을 찾아가서 일행한다. 줄을 합치는 명령을 `:normal`을 이용해 실행해보자.

```bash
:9,11normal J
```

```bash
 9| (9)안녕하세요.
10| (10)종완입니다.
11| (11)반가워요.
12| (12)좋은 하루 되시구요.
13| (13)잘 부탁드립니다.
14| (14)감사합니다.
```

9행에서 `normal J`가 실행되면 다음과 같은 상태가 된다.

```bash
 9| (9)안녕하세요. (10)종완입니다.
10| (11)반가워요.
11| (12)좋은 하루 되시구요.
12| (13)잘 부탁드립니다.
13| (14)감사합니다.
14| ...생략
```

그리고 현재 상태에서의 10행인 `(11)`이 있는 라인에서 `normal J`가 실행된다.

```bash
 9| (9)안녕하세요. (10)종완입니다.
10| (11)반가워요. (12)좋은 하루 되시구요.
11| (13)잘 부탁드립니다.
12| (14)감사합니다.
13| ...생략
14| ...생략
```

마지막으로 또 현재 상태에서의 11행인 `(13)`이 있는 라인에서 `normal J`가 실행된다.

```bash
 9| (9)안녕하세요. (10)종완입니다.
10| (11)반가워요. (12)좋은 하루 되시구요.
```

그 결과 모두 한 줄로 합쳐지는 게 아니라 한 줄씩 띄엄띄엄 합쳐지게 된다. 보통 이걸 원하는 경우는 거의 없다. 따라서 `normal`을 여러 줄에 걸친 편집을 할 때 쓸 때는 조심해야 한다. 

<br>

### `:global`, 패턴으로 줄을 선택해서 명령을 실행할 수 있는 명령

`:global`을 위와는 다른 방식으로 라인별 명령을 실행할 수 있다. 일반적인 명령에서 받는 `{range}`는 시작~끝이 있는 연속된 범위만 받을 수 있지만, `:global`명령을 쓰면, `pattern`을 포함하는 라인들을 선택해서(`:global/pattern/`) 실행시키거나 `pattern`을 포함하지 않는 라인들을 선택해서(`:global!/pattern/`) 실행시키는 것이 가능하다. 연속된 범위가 아닌 떨어져 있는 라인들을 선택해서 명령을 실행시키는 것도 가능한 것이다. `:[range]global`도 명령 앞에 범위(`[range]`)를 받을 수 있는데, 이건, `/pattern/`을 찾을 범위를 설정하는 것이지, `:global/pattern/{cmd}` 뒤의 명령`{cmd}`을 실행시킬 범위를 설정하는 것이 아니다. 이 범위의 라인들에 개별적으로 pattern 매칭을 해보는 것 같으니, 이것도 패턴 매칭 자체는 행별로 한다고 볼 수는 있겠다. 그러나 엄밀히 말해 `{cmd}`를 실행시키는 라인은 `[range]`가 아니라 `[range]`내에서 패턴 매칭해서 걸러낸 라인들이다.

그리고 이 라인들에 대해서 행별로 명령을 실행한다. 그리고 이 때도 명령에 의해 라인의 위치가 변경된다고 해도, 원본에서 매칭되었던 라인들을 찾아서 실행한다고 한다. 원래 라인을 찾는 메커니즘은 `:s`와는 다른데, `:s`의 경우에는 업데이트될 때마다 타깃 라인의 포인터를 바꾼다고 하는데, 정확히 무슨 말이지 잘 모르겠다. Gemini에게서 들은 것이므로 신뢰성도 확실하진 않긴 한데, 개인적으로는 줄의 위치가 변경되는 편집이 있을 때마다 예를 들어 줄이 하나 위로 이동할 만한 편집이면, 다음 행을 가리키는 10이라는 숫자를 9로 업데이트한다거나 하는 방식을 생각했다. 좀더 자세히 물어보니까 편집마다 N번 줄에서 M개의 줄이 추가/삭제되었다는 정보를 계산하고 있고, 이로 인한 델타값을 이용해 다음에 갈 행번호를 찾을 수 있다는 것 같다. 즉, 원래 다음 index(행번호)가 10이었는데, 이번 편집으로 줄이 2개 늘었으면, 다음 index(행번호)도 +2를 해서 12로 바꿔서 찾아간다는 것이다.

`:g`에서 명령이 실행될 라인은 연속된 라인이 아닐 수도 있다. 그래서 다른 전략을 쓰는데 패턴 매칭으로 찾은 라인들에 마킹을 해두는 것이다. vim은 내부적으로 buffer 데이터를 일종의 줄 단위 리스트처럼 관리하므로 그 리스트의 항목마다 임시 마킹 상태를 두어 이걸 켜두는 것이다. 그러면 줄이 어떤 식으로 이동하든, `:g` 명령은 그 마킹을 보고 수정해야 할 줄을 찾을 수 있다. 그래서 결과적으로는`:s`와 비슷하게, 이전 라인에 의한 편집 결과에 영향을 받지 않고, 원래 선택된 줄에 명령이 실행되는 것이다.

그런데 줄을 합치는 경우에는 `:s`와 다른, 좀 특이한 결과를 보인다. 이는 `:g`가 라인을 찾아서 실행하는 로직에 따른 결과일 것으로 보인다. `:g/pattern/`에서는 원래 range로 라인을 선택하는 기능이 없지만, 패턴 문법 중, 라인을 제한하는 기능인 `\%10l`, `\%>8l`, `\%<25l`같은 것을 사용하면, 비슷한 기능이 가능하다.

```bash
 9| (9)안녕하세요.
10| (10)종완입니다.
11| (11)반가워요.
12| (12)좋은 하루 되시구요.
13| (13)잘 부탁드립니다.
14| (14)감사합니다.

```

위와 같은 원본에 다음과 같이 하면, 8행 아래(`\%>8l`), 12행 위(`\%<12l`)에서 패턴 찾는 범위를 제한한다. 검색 패턴 자체는 빈문자열이니 결과적으로 9~11행이 마킹된다. 이 상태에서 줄을 합치는 명령을 해보자.

```bash
:g/\%>8l\%<12l/s/\n/ /
```

```bash
:g/\%>8l\%<12l/normal J
```

위 명령은 둘다 동일하게 다음과 같은 결과를 보인다. 다음 행을 찾는 로직을 `:s`나 `:normal`이 맡는 게 아니라 `:g`가 맡기 때문에 결과가 동일한 것 같다. 그리고 결과는 `:9,11s/\n/ /`나 `:9,11normal J`과도 다르다.

```bash
(9)안녕하세요. (10)종완입니다.
(11)반가워요. (12)좋은 하루 되시구요.
(13)잘 부탁드립니다.
(14)감사합니다.


```

이는 줄이 합쳐지면서 뒷 줄에 있던 마킹이 소멸했기 때문이 아닌가 싶다. 확실하지는 않다. 다만 추측해보면 줄이 합쳐지든 말든, 줄수의 변화에 따라 index의 offset을 조정하는 `:s`는 index 조절 결과 다음 타깃이 이전 줄과 같은 줄이 되어도 별 문제가 없는데, 줄마다 마킹 상태로 체크하는 `:g`의 경우, 줄이 합쳐지면서 마킹도 하나가 되고, 이미 실행한 라인의 마킹은 해제되면서 스킵되는 게 아닌가 싶다. 그래서 9행과 11행에서는 합쳐지는 로직이 실행되었는데, 10행에서는 합쳐지는 로직이 스킵된 것이 아닐까?

또한 몇 가지 실험을 더 해보면, 줄을 `:m`로 이동하는 가운데 줄의 순서가 바뀌거나 줄이 이전 줄로 가버리면, 마킹되었던 라인에서 명령이 실행 안 되는 듯한 모습도 보이는데, 정확히 이유는 모르겠다. 마킹을 찾는 vim의 구현 디테일에 따른 현상이 아닐까 싶다. Gemini가 이야기했던 것 중에 하나는 이번에 실행한 라인 이후의 라인에서 다음 마킹을 찾는다는 이야기가 있었는데, 정확히 테스트 결과에 부합하는 설명은 아니지만, 이런 식의 세세한 로직의 영향이 아닐까 싶다.

<br>

명령어별 Range 및 라인별 명령 실행 방식에 대한 대략적인 정리다.

|     |     |     |
| --- | --- | --- |
| **명령어** | **Range 처리 방식** | **줄 번호 변화 추적 여부** |
| **`:d`, `:m`** | **일괄 처리** | 추적 필요 없음 (한 번에 실행) |
| **`:s`, `:g`** | **행별 실행** | **자동 추적함** (마크/포인터 사용) |
| **`:norm`** | **행별 실행** | **추적 안 함** (순수 줄 번호 의존) |

### 몇 가지 비슷한 동작을 하는 결과를 비교를 해볼만한 명령들을 적어본다.

### 줄 제거하기

```bash
" 9~11행을 한번에 제거 ✅
:9,11d

" 9행 제거, 10행 제거, 11행 제거 (제거하면서 행이 당겨지는데 고려 안하고 제거해서 실제로 9, 11, 13행이 제거됨  ❌
:9,11norm dd

" 9,10,11행을 순차적으로 제거, (제거하면서 행이 당겨지는 걸 고려해서 기대한 대로 9~11행 제거)  ✅
:9,11s/.*\n//

" 9,10,11행을 순차적으로 제거 (제거할 줄을 마킹해두고 제대로 찾아가서 기대한 대로 9~11행 제거)  ✅
:g/\%>8l\%<12l/d
:g/\%>8l\%<12l/norm dd
:g/\%>8l\%<12l/s/.*\n//

```

<br>

### 줄 합치기

```bash
" 9~11행을 한번에 합침 ✅
:9,11j

" 9,10,11행을 순차적으로 합치는데 행이 당겨지는 걸 고려 안 해서 9/10, 11/12, 13/14 행이 합쳐짐 ❌
:9,11norm J

" 9,10,11행에서 다음 줄을 끌어오는데 행이 당겨지는 걸 고려하지만, 한 줄을 더 끌어와서 9~12행이 합쳐짐 ❌
:9,11s/\n/ /

" 9~11행을 합치려면 범위를 하나 줄여야 함 ✅
:9,10s/\n/ /

" 9,10,11행을 순차적으로 합치는데 합쳐진 줄의 마킹이 사라지는 걸로 의심됨, 9/10, 11/12 행만 합쳐짐 ❌
:g/\%>8l\%<12l/j
:g/\%>8l\%<12l/normal J
:g/\%>8l\%<12l/s/\n/ /


```

<br>

### 빈 줄 추가하기 (norm o, s/$/\\r/, g + (put \_, s norm)

```bash
" 9,10,11행에 순차적으로 빈 줄을 추가하는데 행이 밀리는 걸 고려 안 해서 9행 뒤에 빈 줄이 세 개 삽입됨 ❌
:9,11norm o

" 9,10,11행에 순차적으로 빈 줄을 추가. 행이 밀리는 걸 고려해서 기대한 대로 9,10,11행 각각의 뒤에 빈 줄이 하나씩 삽입됨 ✅
:9,11s/$/\r/

" put은 범위가 아니라 주소 하나만 받으므로 범위 방식으로는 각 줄에 삽입하도록 할 수 없고, :g 명령과 조합해야 함
" 9,10,11행에 순차적으로 빈 줄을 추가. 마킹한 줄을 정확히 찾으므로 9,10,11행 각각의 뒤에 빈 줄이 하나씩 삽입됨 ✅
:g/\%>8l\%<12l/put _
:g/\%>8l\%<12l/norm o
:g/\%>8l\%<12l/s/$/\r/

```

| **방식** | **해당 명령어** | **특징** |
| **행별 반복형** | `:normal`, `:list`, `:print` | 지정된 범위의 각 줄을 하나씩 순회하며 명령을 재실행함. |
