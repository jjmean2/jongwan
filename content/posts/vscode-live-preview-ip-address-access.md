## 🎯 목표: "내 폰으로 내 웹사이트를 보고 싶어!"

VS Code의 [**Live Preview**](https://marketplace.visualstudio.com/items?itemName=ms-vscode.live-server)는 마이크로소프트에서 제공하는 확장 프로그램으로 로컬 개발 환경에서 HTML/CSS/JavaScript 파일을 실시간 웹서버로 제공해줍니다. 코드를 저장하면 즉시 브라우저에 반영되어 빠르게 결과를 확인할 수 있죠.

보통 PC에서는 `localhost`로 접속하면 잘 보입니다. 하지만 **스마트폰 실제 기기**에서 접속하려면 PC의 실제 IP 주소가 필요하죠. 그런데 막상 IP로 접속하면 연결이 안 되는 경우가 많습니다. 왜 그럴까요? 네트워크의 **'바인딩(Binding)'** 개념과 함께 해결 방법을 알아봅시다.

---

## 📌 이론 살짝 보기: 왜 IP 주소로 접속이 안 될까?

서버를 띄울 때는 단순히 "포트 번호(예: 3000번)를 연다"라고만 생각하기 쉽지만, 사실은 **"어떤 주소(IP)의 몇 번 방(Port)에서 기다릴 것인가"**를 정해야 합니다. 이를 **바인딩(Binding)**이라고 합니다.

### 1. 리스닝 소켓 (Listening Socket): "문지기"

서버가 처음 띄워질 때 생깁니다. **(프로토콜, 내 IP, 내 포트)**라는 3가지 정보(3-Tuple)를 선점합니다. 이 주소로 들어오는 요청만 받을 수 있습니다.

- 만약 `127.0.0.1:3000`으로 바인딩했다면, 외부에서 내 실제 IP(`10.0.x.x`)로 접속해도 문지기는 응답하지 않습니다. 자기 담당 주소가 아니니까요!

### 2. 커넥티드 소켓 (Connected Socket): "전용 통로"

문지기가 손님을 받으면, 그 손님과 1:1로 대화할 전용 통로를 만듭니다. 이때는 **(내 IP/포트 + 상대 IP/포트 + 프로토콜)**이라는 5가지 정보(5-Tuple)가 완성되어 안전하게 데이터를 주고받습니다.

## 📌 VS Code 설정별 접속 결과 분석

Live Preview 설정의 `Host IP` 값을 어떻게 바꾸느냐에 따라 접속 여부가 달라집니다.

### ✅ 케이스 1: Host IP = `127.0.0.1` (기본값)

- **결과:** PC 내부(`localhost`) 접속만 가능. **외부 접속 불가.**
- **이유:** 서버가 "내 컴퓨터 내부 소켓"만 바라보고 있기 때문입니다. 외부(스마트폰)에서 보낸 신호는 문지기에게 전달되지 않습니다.

### ⚠️ 케이스 2: Host IP = `0.0.0.0`

- **결과:** 접속 가능해야 하지만, Live Preview에서는 **401 에러(권한 없음)** 발생.
- **이유:** `0.0.0.0`은 "내 컴퓨터로 들어오는 모든 주소를 다 받겠다"는 뜻입니다. 하지만 Live Preview는 보안상 모르는 주소의 접근을 능동적으로 차단하기 때문으로 보입니다.

### 🚀 케이스 3: Host IP = `실제 내 IP (예: 10.0.2.153)`

- **결과:** **접속 성공!**
- **방법:** VS Code 설정에서 `Live Preview: Host IP`를 찾아 본인의 실제 할당된 IP 주소를 직접 입력하세요.

---

## 🔍 꿀팁: `lsof`로 바인딩 상태 확인하기

내가 설정한 대로 서버가 잘 돌아가고 있는지 궁금하다면 터미널에 아래 명령어를 입력해 보세요. (8888 포트 기준)

```bash
lsof -n -P -i TCP:8888 -sTCP:LISTEN

```

- **NAME** 컬럼에 `127.0.0.1:8888`이 뜨면? -> PC 안에서만 접속 가능.
- **NAME** 컬럼에 `10.0.2.153:8888`이 뜨면? -> 스마트폰 접속 준비 완료!

## 📱 최종 체크리스트: 아이폰에서 접속하려면?

1. **IP 바인딩:** VS Code 설정에서 `Host IP`를 맥(PC)의 실제 IP 주소로 설정합니다.
2. **동일 네트워크:** 아이폰과 맥이 **같은 와이파이(Wi-Fi)**에 연결되어 있어야 합니다.
3. **방화벽 확인:** 맥의 보안 설정에서 들어오는 연결을 막고 있지는 않은지 확인하세요.

이제 책상에 앉아 스마트폰으로 직접 화면을 터치하며 웹 개발을 테스트해 보세요! 🚀

## 💡 개선하면 좋을 점

1. **IP 주소 확인법 추가:** 독자들이 자신의 실제 IP(`10.0.x.x`)를 어디서 확인하는지(Windows의 `ipconfig`, Mac의 `ifconfig`나 설정 창) 짧게 언급해주면 더 친절한 글이 될 것 같아요.
2. **보안 주의사항:** 외부 IP 바인딩은 공공 와이파이에서 보안 위험이 있을 수 있다는 짧은 경고를 곁들이면 전문가스러운 느낌이 납니다.
